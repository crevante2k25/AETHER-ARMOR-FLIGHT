# D. ARMOR CHARACTER — HIGH PRIORITY

Build a visually recognizable original armored character. Do not leave the final deliverable as a collection of primitive cubes.

Required visual details:
- Distinctive helmet and faceplate.
- Layered chest, abdomen, shoulder, arm, and leg plating.
- Articulated mechanical joints.
- Cyan chest reactor.
- Circular palm repulsor emitters.
- Boot and back thrusters.
- Metallic red-and-gold material separation.
- Emissive cyan components.
- Consistent proportions and silhouette.
- Appropriate flight and combat poses.

Preferred asset workflow:
1. Search for a suitable legally reusable rigged model.
2. If none is suitable, generate or model an original armor asset.
3. Refine the geometry, materials, proportions, and joints in Blender or an equivalent 3D tool.
4. Export as GLB/glTF with textures and skeleton where supported.
5. Import into Godot.
6. Verify scale, facing direction, material assignments, animation playback, and mobile rendering.

If automated 3D generation is unavailable, build a detailed modular character using meshes and procedural geometry, with clearly separated armor panels, custom materials, reactor geometry, palms, and thrusters. Treat this as a replaceable prototype, not as proof that a final high-quality character model exists.

Do not invent downloadable model URLs or claim a model has been generated when it has not.

# F. FLIGHT PHYSICS

Implement a collision-aware, tunable flight system.

Required behavior:
- Grounded state and takeoff.
- Stable hover.
- Forward/backward and lateral movement.
- Vertical thrust.
- Acceleration and deceleration.
- Maximum speed.
- Air drag.
- Boost with energy consumption and regeneration.
- Smooth turning and controlled banking.
- Collision response near buildings.
- Landing.
- Safe recovery if stuck.

Use a consistent physics timestep and frame-rate-independent calculations.

Use CharacterBody3D and collision-aware movement for the first implementation unless an experimentally verified reason supports another approach.

Do not teleport the player through obstacles or bypass collision to simulate flight.

Expose tunable values for speed, acceleration, drag, hover stability, boost, and camera sensitivity.

Create a small flight test arena first. Do not build the entire city before flight works.
